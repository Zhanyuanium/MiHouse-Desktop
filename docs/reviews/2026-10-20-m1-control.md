# M1 control layer — 2026-10-20

Completes the control surface after live testing of a real account.

## What changed

- `IDeviceController` sits between the UI and the cloud client. It resolves the device spec
  (reported `spec_type` first, model index as fallback), applies `ControlDid` for split
  channels, filters a channel's services, reads/writes properties and invokes actions.
- `spec_type` from `home_device_list` is preserved on `MiDevice`.
- Split channels reject any `siid` other than `ChannelSiid` before a request is sent, so a
  stray key can never drive another circuit of the same parent.
- Actions render as cards: no-input buttons, and typed inputs (bool, integer with value list,
  numeric with range, string). Every action is confirmed in a dialog; destructive types get an
  irreversible warning; `unbind` actions are hidden because unbinding belongs to the account,
  not to a device client.
- Writes show the written value immediately, then read it back only when the property is
  readable; a failed read-back reports "已写入，当前值未确认" instead of a false write error.
- Errors carry an explicit origin: `MiHomeException.IsDeviceError` is true only for device-level
  result codes. The UI shows a device-rejection message only for those; everything else is a
  neutral request failure. Unknown exceptions never echo their message.
- 64-bit action inputs are parsed exactly and validated against the spec range, step and value
  list; they never pass through `double`.

## Review

Two rounds of review (Core and desktop) produced no P1. The P2s found were:
cross-channel operations not guarded, int64 precision loss, write/read-back conflation,
negative-code misattribution, list errors classified as device errors. All are fixed; the
reviewers confirmed the Core guard and the UI fixes.

## Live evidence

- Split-channel writes now reach the parent (spot lights and switches work).
- The air conditioner previously froze the window twice: 88 properties in a non-virtualizing
  panel, then `Slider.TickFrequency` on a `0..999999.99 step 0.01` range. Both are fixed; the
  list scrolls to the bottom without blocking.
- ECO/Heater return `-704053100` while the unit is in fan mode; the UI now explains that the
  device rejected the setting rather than showing a raw code.
- The range hood exposes Toggle / Stop Dry Cleaning / Execute Dry Cleaning with a confirmation
  dialog; Unbind is hidden.

## Known limits

- The UI is still English for spec descriptions (i18n deferred).
- All 88 air-conditioner properties are shown; grouping/collapsing secondary services deferred.
- `gethome` paging beyond 300 homes is not implemented.
