# M2 scenes and state freshness — 2026-10-20

## Scenes

- `GetScenesAsync` → `POST /app/appgateway/miot/appsceneservice/AppSceneService/GetSimpleSceneList`
  with `{"app_version":12,"get_type":2,"home_id":"<string>","owner_uid":<number|string>}`.
  Reads `result.manual_scene_info_list` (`scene_id`, `name`, `enable`, `icon_url`).
- `RunSceneAsync` → `.../NewRunScene` with
  `{"scene_id","scene_type":2,"phone_id":"null","home_id":"<string>","owner_uid":...}`.
  Success is the top-level `code == 0`; the cloud reports no per-action result.
- Shared homes use the home owner's uid, never the signed-in account's. `home_id` is a string
  in the scene API even though the device API uses a number.
- UI: a 场景 flyout per home, cached until the home changes or the flyout is refreshed; every
  run asks for confirmation; rows are keyed by scene id so a refresh cannot reset a running
  row; disabled scenes keep a marker but can still be run.

Live check: one shared home returned 5 scenes, another 7, the empty homes 0. The UI showed the
list for the populated home and the correct empty state for the others.

## State freshness

There is **no usable push channel** for a legacy `xiaomiio` session:

- `/v2/miotspec/prop_changed` is a plugin-to-host report, not a subscription;
- the SSE path exists only inside the APK (`SmartHomeRc4ChunkApi`), with no documented URL and
  no public implementation;
- the MQTT broker that third parties use is the OAuth2 `ha` channel, which a `serviceToken`
  cannot open.

So the client polls: while a device detail is open it re-reads that device's readable
properties every 6 s, backing off to 12 s and 30 s after failures, and only updates rows that
have no pending edit and no unconfirmed optimistic value. Polling stops on selection change,
pane close, sign-out, page unload and window deactivation, and resumes on activation.

## Review

| # | Sev | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | P2 | Refreshing scenes rebuilt rows and dropped the running flag, allowing a second run. | Rows keyed by scene id; refresh merges and preserves `IsBusy`; refresh disabled while anything runs. |
| 2 | P2 | A failed retry cleared the "unconfirmed" guard, letting polling overwrite the optimistic value. | The flag is only cleared by a write plus an accepted read-back. |
| 3 | P2 | `PeriodicTimer` kept a tick from the slow request, skipping the backoff. | Sequential `Task.Delay` per interval after each poll. |

Core scene review found no P1/P2; two P3 regression tests were added.

## Limits

- Scene execution is fire-and-forget: the cloud returns success before the individual device
  actions finish, and there is no per-action result to display.
- Polling is 6 s for the open device only; the list's online flags refresh on manual refresh.
- No push means at least a few seconds of staleness while the pane is open.
