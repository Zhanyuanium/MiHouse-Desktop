# M1 review — 2026-10-20

Two independent reviews: core services (Cloud/Spec/Auth) and the desktop layer
(App/Views/ViewModels/Security). Both were re-checked after the fixes below.

## Core findings

| # | Sev | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | P1 | Property writes and actions ignored operation-level `code`, so device-side failures looked successful. | `SetPropertyAsync` requires a non-empty `result` array and accepts only entry codes 0/1. `InvokeActionAsync` requires a `result` object, rejects a non-zero inner code, and returns `out` (or an empty array). |
| 2 | P1 | Online state read `online` while the API sends `isOnline`, so devices always appeared offline. | `isOnline` is preferred, `online` is a fallback; bool, number and string forms are accepted. |
| 3 | P2 | Non-2xx responses and a missing `code` could be treated as success; an HTML 403 surfaced as `FormatException`. | HTTP status is checked before any decoding (401/403 keep their code and a session-expired message). A missing or non-numeric `code` is a protocol error. |
| 4 | P2 | QR polling ignored the ticket deadline. | An expired ticket throws before any request; each poll is bounded by `min(120 s, remaining)`. |
| 5 | P2 | Spec index selection depended on array order, and the published index is not version-sorted. | The highest `version` per model wins (missing = 0). |
| 6 | P3 | Nonce used only 63 random bits; empty field list produced a doubled `&`; a test decoded forms with the wrong helper. | Nonce uses 8 bytes from `RandomNumberGenerator`; empty-field signatures have a single separator; tests use `WebUtility.UrlDecode` and pin a `+` value. |

## Desktop findings

| # | Sev | Finding | Resolution |
| --- | --- | --- | --- |
| 7 | P1 | Sign-out could report success while `session.dat` remained, causing an automatic re-login. | `ClearAsync` deletes directly and propagates I/O failures. |
| 8 | P2 | Saves were not serialized, shared one temp file, and could publish after cancellation. | One gate for all store operations, unique temp files, cancellation check before the atomic move. |
| 9 | P2 | A late QR image failure cancelled an unrelated password login. | Switching modes clears the QR source; the failure callback validates the attempt and current mode. |
| 10 | P2 | Light-dismissing the detail pane left the device selected, so it could not be reopened. | Closing the overlay clears the selection. |
| 11 | P3 | Selection changes stole keyboard focus in the inline pane. | Focus moves only when the overlay opens. |
| 12 | P3 | Typed passwords survived a switch back to QR mode. | Leaving password mode and `Stop()` clear the password. |

## Cross-checks

- The shared `HttpClient` previously had an infinite timeout. The app now registers two:
  API at 30 s and auth at 300 s, while the auth service still enforces its own per-poll budget.
- Exception text shown in the UI comes from server `message`/`description`; no session tokens or
  response bodies are included.

## Verification

- Release build with `-warnaserror` clean; 54 tests pass; `dotnet format --verify-no-changes` clean.
- App launches at 1280×840 logical pixels; the login page shows a QR fetched from the live
  Xiaomi endpoint; password mode round-trips.
